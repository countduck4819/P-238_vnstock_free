# Agentic Development Lifecycle (ADLC)

ADLC là luật lifecycle portable cho repo có `.agents/`. File này chỉ giữ quyết định canonical; chi tiết project nằm trong `.project-contexts/`, chi tiết tool nằm trong skill hoặc setup guide. Khi dùng làm template cho project mới, không copy tên board, branch, service, URL, command hoặc owner từ project khác: bootstrap lại project context từ source của project đích.

## Plugin System

Mỗi chức năng ADLC là 1 plugin, enable/disable trong `.agents/plugins/plugins.yml`
(`python3 .agents/plugins/loader.py list|status|load|test`). **12 plugins:**
jira-gate, gitflow-gate, session-lifecycle, quality-gates, workflow-engine,
parallel-gates, subagent-providers, ralph-loop, agent-teams, defensive-patterns,
glossary, dsh-adapter. Catalog: `.agents/plugins/registry.json`. Tạo plugin mới:
copy `.agents/plugins/template/`, chi tiết `.agents/references/plugin-development.md`.
DSH adapter: `.agents/plugins/dsh-adapter/README.md`.

## Quick Gate

1. Đọc `.project-contexts/project-context.md`, resolve workspace liên quan, rồi chỉ đọc context/source cần cho task. Nếu context chưa có hoặc đã stale, bootstrap/cập nhật theo phần **Project Context Bootstrap** trước khi suy luận framework, command, GitFlow hay work tracking.
2. Chọn luồng nhẹ nhất theo risk. Không tạo workflow run/artifact nếu task không cần audit.
3. Làm thay đổi nhỏ nhất, kiểm chứng tỷ lệ với risk, rồi bàn giao file đổi, lệnh đã chạy, kết quả và risk còn lại.

### Parallel Gates (P0)

Ba gate đầu — **Jira**, **GitFlow**, **Session Lifecycle** — chạy song song thay vì tuần tự. Dùng `parallel_gates.py fanout` để fan-out, `join` để tổng hợp kết quả. Chi tiết: `.agents/plugins/parallel-gates/README.md`.

### Lazy Loading (P0)

Chỉ load reference khi skill cần — không load toàn bộ `.agents/references/` upfront. Dùng `lazy_loader.py load --skill /sec` để load on-demand. Skill → reference mapping: `.agents/references/skill-reference-map.md`.

### Glossary

Canonical terminology cho ADLC — 1 term per concept. Khi không chắc term nào đúng, đọc `.agents/references/glossary.md` trước.

Không log PII/token/secret, không hardcode secret, không nối chuỗi SQL. Code identifiers, tên branch, commit subject và Jira title dùng tiếng Anh ngắn gọn; Jira description, Jira completion/blocker comment, Confluence/ADR body và handoff dùng tiếng Việt trừ khi user hoặc tài liệu nguồn yêu cầu ngôn ngữ khác.

## Quick Decision Tree

Bảng tra nhanh để chọn luồng mà không cần đọc hết các gate bên dưới. Chi tiết và ngoại lệ vẫn theo section tương ứng; khi mâu thuẫn, policy risk và section chi tiết có quyền ưu tiên.

- Hỏi đáp / giải thích / review chỉ đọc / typo docs → không Jira, không run, không skill nặng. Trả lời trực tiếp.
- Docs/metadata nhỏ (`micro`) → `/dev`. Không test-first, không audit.
- Bugfix/refactor không đổi contract (`code_change`) → `/qc` regression → `/dev`; `/sec` chỉ khi chạm auth/data/logging/dependency/container.
- Feature/behavior/API/UI/auth/data (`feature_change`) → `/ba` (nếu rule chưa rõ) → `/qc` test-first → `/dev`; thêm `/api` `/ux` `/sec` theo bề mặt bị chạm.
- Auth boundary mới / regulated data / migration / payment/medical / deploy risk / user yêu cầu audit chặt (`critical_change`) → luồng `feature` + approval trước mutation + evidence đầy đủ.
- Deploy candidate / handover chính thức → `/release` sau khi có QC/dev/sec/devops evidence.
- Batch không giám sát / qua đêm / Claw Team → **Autonomous Handoff Gate**: pre-flight brief một lần rồi chạy, không hỏi lại giữa chừng.

Cổng bắt buộc theo thứ tự khi có delivery work: **Jira Gate** (nếu là delivery) → **GitFlow Gate** (trước khi sửa code) → **Session Lifecycle Gate** (get up to speed/healthcheck trước khi làm) → skill theo intent → **Quality Gates** → handoff theo **Definition Of Done**. Không tự nâng risk chỉ vì có HTTP/API/Jira (xem **Lean Mode / Token Budget**).

## External AI Provenance

Mọi nội dung do ADLC tạo hoặc cập nhật trên hệ thống ngoài phải có một footer
`ADLC AI provenance` ở cuối: PR/MR description hoặc comment, Jira
description/comment, Confluence page/comment và PR/MR review.

```markdown
---
> **ADLC AI provenance**
> - Models: `<provider/model-id> (<role>); ...`
> - Coding/agent tools: `<tool> (<role>); ...`
> - ADLC version: `<x.y.z>`
```

Liệt kê toàn bộ model và coding/agent tool đã đóng góp đáng kể (không chỉ agent
publish cuối); `Coding/agent tools` ghi `ADLC Code` (không phải `Claude Code`)
khi phiên chạy dưới ADLC Code (kiểm tra env `ADLC_CODE` trước `CLAUDECODE`) —
xem thứ tự resolve và tool detection đầy đủ ở `.agents/references/provenance.md`.
`ADLC version` lấy đúng nguồn canonical qua `agent_trace.adlc_version()`,
không đoán số. Không suy đoán giá trị — model ID thiếu thì ghi
`unknown (runtime không cung cấp)`, tool không dùng thì `none`, version không
resolve được thì `unknown`. Không đưa
prompt, token usage, secret, credential, PII hoặc raw log vào footer;
upsert/replace footer hiện có thay vì nối nhiều footer. Provenance là metadata
audit, không phải bằng chứng code đã PASS quality, security, CI hoặc release
gate. Mọi trace do `agent_trace.py` emit mang `adlcVersion` trong metadata và
phải khớp footer. PR/MR description do ADLC tạo còn phải có đúng một dòng cam
kết trách nhiệm của người tạo PR (do `gitflow_tool.py ship` tự chèn). Chi tiết
từng field, đồng bộ Langfuse (`--model-used`, `--release-advisory`…) và dòng
cam kết trách nhiệm ở `.agents/references/provenance.md`; đọc khi thực sự
publish hoặc emit trace.

## Lean Mode / Token Budget

Với task tối ưu ADLC, phân tích quy trình, chỉnh tài liệu/runner/skill nội bộ, hoặc user nói rõ "không cần Jira/quy trình phức tạp", dùng `micro` hoặc `code_change` nhẹ và không tạo Workflow Control run mới trừ khi user yêu cầu audit trail riêng. Lean Mode chỉ giảm ceremony (risk class, run/artifact, multi-agent), không thay thế **Jira Gate**: delivery work — kể cả thay đổi quy trình, tài liệu hoặc skill đáng kể — vẫn đi qua Jira Gate và vẫn hỏi user đúng một lần khi chưa có ticket; agent không tự skip Jira, chỉ user mới được chọn bỏ qua (nói rõ trong prompt hoặc trả lời câu hỏi của Jira Gate). Nếu task chỉ phân tích history, ưu tiên đọc run artifact, Langfuse metadata và git diff hiện có; không spawn thêm agent.

Multi-agent chỉ dùng khi user yêu cầu hoặc scope có từ hai phần độc lập thật sự. Nếu dùng subagent, mỗi agent phải có brief ngắn, phạm vi file rõ, điều kiện dừng rõ, và không lặp review quá hai vòng cho cùng một finding. Sau vòng thứ hai, primary agent tự quyết định sửa nhỏ hoặc báo blocker, không tiếp tục ping-pong.

Khi có Workflow Control run, agent phải mark `RUNNING` trước khi làm bước đáng kể và `DONE/ERROR/SKIPPED` ngay khi xong để có `durationMs`. `update-step` tự chụp token usage cục bộ từ session log của coding agent hiện tại (`usage_snapshot.py`: Claude Code, Codex CLI) — không cần hook hay khai báo tay; chi tiết override và adapter ở `.agents/references/workflow-control-operations.md`.

Với API/external integration bình thường, không tự nâng lên `critical_change` chỉ vì có HTTP/API/Jira. Chọn:

- `feature_change` khi là endpoint/wrapper có auth/test/IDP nhưng không đổi data model, migration, deploy topology, regulated workflow hoặc production runtime.
- `critical_change` chỉ khi có auth boundary mới/rủi ro regulated data, migration/persistence, payment/medical, production deploy risk, cross-team architecture decision hoặc user yêu cầu audit chặt.

## Adaptive Planning / Workflow Evaluation

Workflow selection có ba dimension độc lập: `risk`, `artifactDepth` và
`testStrategy`. Khi task mơ hồ hoặc cần giải thích routing, dùng composer
read-only để đề xuất workflow, approval policy và step `EXECUTE/SKIP` kèm lý do:

```bash
python3 .agents/orchestration/scripts/workflow_runner.py compose \
  --request "<task request>" [--path <affected-path>] --json
```

Composer routing đi theo triage nhiều tầng thay vì keyword ưu tiên: intent gate (động từ read-only → `micro`), keyword chain release → critical → ai → code → feature → micro với path/file reference phân loại riêng (docs/`*.md` → `micro`; `migrations/` thật → `critical_change`; path chạm bề mặt bảo mật → bắt buộc `/sec`), rồi fallback `code_change` + approval cho request mơ hồ với `/ba` và `/sec` vẫn `EXECUTE` (fail closed). Escalation chỉ đúng khi có mutation intent kèm critical surface. Từng tầng ở `.agents/references/workflow-control-operations.md`.

Composer không tạo Workflow Control run, không sửa source và không mutate Jira,
Confluence, Git hoặc hệ thống ngoài. Kết quả là recommendation; policy risk,
project context, explicit user scope và source contract vẫn có quyền ưu tiên.
`micro`/read-only không được tạo artifact hoặc approval ceremony chỉ vì đã gọi
composer.

Workflow policy phải được regression-test như code:

```bash
python3 .agents/orchestration/scripts/workflow_runner.py evaluate
python3 .agents/orchestration/scripts/workflow_runner.py compile-contract --check
python3 .agents/orchestration/scripts/workflow_selftest.py
python3 .agents/orchestration/scripts/agent_eval.py validate
```

Golden cases chỉ chứa input synthetic và invariant ổn định về routing/safety;
result không lưu raw request. Deterministic evaluator là policy gate.

Output của agent có corpus riêng — `evals/agent-cases.json`: prompt cố định trên
fixture cố định, chốt bằng **hành vi quan sát được** (file nào đổi, regex nào
có/không, tool nào được gọi), không chốt văn bản vì output model không tái lập.
`agent_eval.py validate` miễn phí và an toàn cho CI; `agent_eval.py run` tốn
token nên là quyết định của người — đúng luật ở trên: deterministic evaluator là
gate, model evaluation là audit evidence.

Generated `.agents/orchestration/workflow-contract.json` resolve workflow/skill
inputs, output, gate và failure mode từ source canonical. Không hand-edit file
generated; sửa `workflow-control.json`/skill manifest rồi chạy
`compile-contract`, sau đó `--check` phải PASS.

Với audited run, step có thể ở `PENDING`, `RUNNING`, `AWAITING_APPROVAL`,
`REVISING`, `BLOCKED`, `DONE`, `ERROR` hoặc `SKIPPED`. `BLOCKED`/`REVISING`
phải có reason đã sanitize; `SKIPPED` luôn lưu skip reason. Khi `DONE` và output
tồn tại, runner lưu SHA-256. `resume-run` phải xác minh hash và fail closed nếu
artifact đã đổi hoặc mất; resume point đến từ `run.json`, không từ chat memory.
Các rule này chỉ áp dụng cho run audit tùy chọn, không làm task đơn phải tạo run.

## Jira Gate

Không hỏi Jira cho hỏi đáp, giải thích, brainstorm, review/status chỉ đọc, tra cứu, typo/docs nhỏ không đổi behavior/quy trình.

Với delivery work như feature, bugfix, refactor, code/test, API, auth, data, UI, runtime, migration, deploy hoặc thay đổi quy trình đáng kể:

1. Tìm Jira key hoặc full URL trong prompt. Nếu có `.project-contexts/work-tracking.json`, dùng nó cho default site/project, board và Confluence anchor; nếu chưa có, dùng explicit URL/user input trước.
2. Nếu chưa có ticket, hỏi đúng một lần:

   ```text
   Task này có cần gắn Jira không?
   1. Nhập Jira key/URL
   2. Bỏ qua Jira
   ```

3. Có ticket thì dùng `$twg` typed read để xác minh, đọc scope/AC/link liên quan và so với request. Scope mâu thuẫn thì hỏi user.
4. Ticket không tồn tại thì hỏi có muốn tạo không. Chỉ tạo sau khi user đồng ý, đọc create metadata trước, không đoán custom field.
5. User chọn bỏ qua thì tiếp tục task và ghi `Jira: skipped by user`; không hỏi lại trong cùng task.

Agent chấp nhận key, `/browse/<KEY>`, URL có `selectedIssue=<KEY>`, hoặc URL có segment dạng `<PROJECT>-<NUMBER>`. Project URL chỉ là context, không phải ticket. Không dùng recent board/space làm default; recent chỉ là gợi ý khi config và prompt đều thiếu dữ kiện.

Ticket mới set assignee là `me`, không tự set reporter. Chỉ tự chọn sprint khi board đã rõ, sprint còn active theo ngày, `originBoardId` khớp và chỉ có một kết quả. Không rõ thì tạo vào backlog hoặc hỏi user.

Khi project bắt buộc `Due date`, luôn set field này lúc tạo ticket/subtask (chi tiết Due date, custom field option/select, board/project/sprint selection và Jira REST fallback ở `.agents/references/jira-operations.md`; đọc khi thực sự tạo/cập nhật ticket).

Khi task có ticket hoàn tất hoặc bị block sau khi đã làm việc đáng kể, Jira completion comment bằng TWG bằng tiếng Việt phải ghi: kết quả, file/module chính, nhánh code, PR/MR link nếu đã tạo, verification, risk/blocker và footer `ADLC AI provenance`. Nếu `/qc` có integration/E2E execution, comment totals, environment/ref, defect và link evidence native; link Confluence workflow E2E summary khi đã publish. Không comment raw report/log, token, secret, PII hoặc payload nhạy cảm.

## GitFlow Gate

Trước khi sửa code/test/runtime, `/dev` kiểm tra branch hiện tại và work-tracking context nếu có. Không code trực tiếp trên protected branch được project khai báo. Với delivery work có Jira key, dùng GitFlow project để chọn branch type/base/target. Khi ticket, branch type, base/target và checkout sạch đều xác định rõ từ request cùng project context, agent tự fetch remote base mới nhất rồi tạo/checkout branch phù hợp, không hỏi user xác nhận lại. Chỉ dừng hỏi khi branch type/base/target còn mơ hồ, checkout có thay đổi không liên quan, branch đã tồn tại nhưng lệch base, hoặc thao tác có nguy cơ ghi đè/mất thay đổi. Khi tạo branch, fetch remote base được project cấu hình rồi tách từ remote ref đó; tên branch có segment `git config user.name` dạng slug và có Jira key khi có ticket. Với docs nhỏ hoặc task đã skip Jira, báo rõ đang dùng branch hiện tại hoặc bỏ qua branch creation.

Với một task đang chạy, không tạo Git worktree: làm trong checkout chính trên đúng feature/bugfix/hotfix branch để user thấy trực tiếp bằng `git status`. Checkout chính có thay đổi không liên quan khiến switch branch không an toàn thì dừng và hỏi cách bảo toàn; không tạo worktree chỉ để đi vòng qua dirty checkout. Worktree **bắt buộc** khi có từ hai task độc lập thật sự được chạy song song trong cùng một Git repo, hoặc khi phát hiện agent/AI khác đang hoạt động cùng repo (session ledger `ACTIVE` khác trong `.agents/runs/sessions/`, `git worktree list` có worktree lạ, Agent Teams task đang chạy) — khi đó không chen vào checkout chính. Mỗi worktree vẫn một branch GitFlow riêng và mọi gate như checkout chính; primary agent giữ mapping `task -> workspace/worktree -> branch -> base/target -> owner/status`; trước khi build/test/runtime trong worktree phải qua **Parallel Runtime Readiness Gate** và handoff phân biệt `static-ready`, `runtime-ready` hoặc `runtime-serialized`. Coordination, readiness, resolve repo/submodule, protocol/credential và luồng `gitflow_tool.py` (`ensure-branch`, `ship`, `mr-link`) ở `.agents/references/gitflow-operations.md` và `.agents/references/parallel-worktree.md`.

Mặc định, ngay khi code/test và verification trong luồng `/dev` đã đạt trên đúng feature/bugfix/hotfix branch (không phải protected branch), agent tự commit thay đổi với message ngắn gọn theo convention của project — không cần user yêu cầu commit riêng mỗi lần. Agent không bao giờ tự commit lên protected branch, không tự force-push và không tự merge. User có thể yêu cầu dừng ở bước bàn giao (bỏ auto-commit/PR) nếu muốn tự review trước; khi đó `/dev` bàn giao file đổi, lệnh đã chạy, risk và trạng thái branch để user tự commit.

Sau khi `/dev` commit xong, mặc định dùng `/devops` mở ngay một **draft/WIP PR/MR** cho user review. PR target lấy từ GitFlow của project hoặc remote default branch đã xác minh. Description bắt buộc: **Jira hoặc Confluence nghiệp vụ**, **author**, **assignee** (nếu có), mục tiêu/phạm vi và footer `ADLC AI provenance`. Sau tạo MR (kể cả draft), luôn gọi `/review` trừ khi user skip (IDP chỉ áp cho backend cung cấp API, FE/mobile ghi `N/A`), và comment Jira ticket với branch/MR link ngay khi tạo draft. Nội dung review chi tiết (checklist, radar, ma trận an ninh, bảng tác động) theo skill `review` và `.agents/references/gitflow-operations.md`. Không đổi Verification gate. User có thể yêu cầu bỏ qua auto-PR.

`/review` tự đánh giá release readiness từ finding và evidence, không chờ author khai:
`BLOCK — DO NOT MERGE` khi còn lỗi có khả năng gây auth bypass, lộ secret/PII, data
loss/corruption, phá contract tương thích, crash luồng chính, migration/deploy không an
toàn hoặc finding critical/high tương đương; `WARNING — NOT RELEASE-READY` khi thiếu
evidence bắt buộc hoặc phạm vi heavy chưa review đủ để kết luận. Mỗi cảnh báo phải cite
finding cụ thể, không hạ mức chỉ vì chưa có scanner. Không thấy blocker thì chỉ được ghi
`NO RELEASE BLOCKER IDENTIFIED` — đó không phải release certification. Khi có cảnh báo mở,
review phải ghi rõ ADLC/model chỉ cung cấp decision-support: người approve/merge chủ động
nhận residual risk. Rubric và câu chữ chuẩn ở skill `review`.

## Session Lifecycle Gate

Áp dụng cho delivery work (`code_change` trở lên); hỏi đáp, review chỉ đọc và task `micro` không thêm ceremony nào. Chi tiết thao tác, schema và checklist ở `.agents/references/session-lifecycle.md`.

- **Get up to speed trước khi làm:** đọc session ledger (`session_ledger.py list`) và khớp task/branch để resume thay vì suy luận lại hoặc hỏi lại user; xem `git status` + `git log --oneline -20`; chạy healthcheck/smoke command của workspace nếu project context đã khai báo. Môi trường đang hỏng thì sửa trước, không chồng thay đổi mới lên nền hỏng. Healthcheck chưa khai báo thì ghi `Healthcheck: NOT CONFIGURED`; không đoán command.
- **Session ledger:** task nhiều bước hoặc có khả năng bị ngắt phiên thì upsert ledger qua `session_ledger.py` sau mỗi bước đáng kể (bước xong + evidence, việc còn dở, blocker), `finish` khi kết thúc. Nhiều agent trên cùng repo thì **`claim` path trước khi sửa** — claim bị từ chối là tín hiệu phối hợp, không phải để bỏ qua. Ledger là local state git-excluded, không chứa secret/PII/raw log.
- **Task checklist máy-đọc-được:** với `feature_change`/`critical_change`, sau khi AC rõ, tạo `.agents/runs/task-list.json` **qua `task_list_tool.py`** — không sửa tay. Tool cưỡng chế luật: `pass` bắt buộc evidence, từ chối pass vượt thứ tự, `validate` phát hiện item bị viết lại để che việc chưa xong. Scope thật sự đổi thì thêm item mới và cite nguồn quyết định.
- **Batch clarification:** gom **mọi** chỗ mơ hồ thành một đợt hỏi duy nhất qua `clarify.py ask` trước khi implement; sau khi gate đóng thì `clarify.py note` ghi assumption rồi đi tiếp, không dừng run.
- **Stop guard:** còn bước `PENDING`/`RUNNING` hoặc item task-list chưa `passes` thì Stop hook (`loop_guard.py`) chặn kết thúc lượt và nêu việc còn nợ. Luật này do harness giữ, không dựa vào việc agent nhớ.
- **Clean handoff:** kết thúc phiên không để file rác/untracked ngoài scope, không process/server lơ lửng do phiên này khởi động, ledger và task list phản ánh đúng trạng thái cuối. Đây là một phần của **Definition Of Done**.

### Defensive Patterns

Khi viết multi-agent workflow, subagent delegation hoặc overnight batch, tuân thủ 7 defensive patterns: report orthogonal outcomes, honor public contracts, async state ≠ sync state, dispose reach quiescence, contain callback exceptions, never hand untrusted output, unlink link-shaped paths. Chi tiết: `.agents/references/defensive-patterns.md`.

## Autonomous Handoff Gate

Áp dụng khi user giao một batch task chạy không giám sát (qua đêm, unattended, hoặc qua Claw Team). Mục tiêu: quyết định trước mọi tình huống để giảm human-in-loop — agent hỏi thiết lập kỹ **một lần duy nhất** trước khi chạy, rồi thực thi toàn bộ batch mà không hỏi lại user giữa chừng.

Độ sâu pre-flight scale **theo độ mơ hồ** của yêu cầu, không one-size-fits-all: task rõ (bugfix, feature nhỏ có AC) chỉ cần checklist tối thiểu; batch nhiều task hoặc feature lớn cần thêm câu hỏi boundary/domain/data/integration cho bề mặt bị chạm; yêu cầu mơ hồ toàn hệ thống ("làm cả app cả web", "làm full", "xây toàn bộ hệ thống") thì agent **không nhận batch qua đêm** khi chưa hỏi đủ bộ câu hỏi theo doc-set inception (BRD/PRD/Technical Spec/Quản trị — xem `.agents/references/inception-session.md`) hoặc chưa có inception session; user không trả lời đủ phần cốt lõi thì thu hẹp scope thành các task rõ, không đoán thay. Ba bậc câu hỏi cụ thể ở `.agents/references/autonomous-overnight.md`; bậc nào cũng hỏi **một lượt duy nhất**.

Pre-flight interview bắt buộc trước khi batch bắt đầu, kết quả ghi vào `.agents/runs/autonomous-brief.json` (schema `autonomous-brief.schema.json`, local git-excluded): task list với `verify_steps` E2E, Jira per task (**Jira Gate vẫn áp dụng** nhưng hỏi gộp, không hỏi lại giữa batch), quyền git (mặc định commit + push + draft MR; `merge_on_green` chỉ merge khi CI xanh trên đúng head SHA, không advisory `BLOCK`/`WARNING` mở, target thuộc GitFlow — không bao giờ merge vào `main`/`release/*`), budget + escalation (gặp quyết định ngoài brief hoặc bị chặn thì ghi blocker vào ledger/task list rồi theo `record-and-continue` mặc định hoặc `stop-batch`, không tự bịa quyết định), và runtime/secret được phép dùng.

Trong lúc chạy, batch tuân đủ các gate khác (GitFlow, Session Lifecycle, Quality, worktree khi song song). Sáng hôm sau, handoff tổng hợp bắt buộc: bảng `task -> branch -> MR link -> CI status -> merged?/blocker`, evidence theo risk, ledger/task list đúng trạng thái cuối. Merge tự động theo brief là quyết định chấp nhận residual risk của user đã ký brief. Chi tiết checklist pre-flight từng bậc và vận hành Claw Team ở `.agents/references/autonomous-overnight.md`.

## ADR / Confluence Gate

ADR là Architecture Decision Record: ghi lại một quyết định kiến trúc quan trọng cùng context, option đã cân nhắc và consequences. Confluence là nơi publish/share nếu project khai báo trong `.project-contexts/work-tracking.json`; repo giữ bản ADR versioned tại `docs/adr/` trừ khi workspace context khai báo path khác.

Không tạo ADR/Confluence update cho typo, docs nhỏ, bugfix cục bộ, refactor không đổi kiến trúc, hoặc quyết định đã được policy/schema hiện có bao phủ. Có Jira ticket không tự động kéo theo ADR/Confluence; chỉ tạo khi task thỏa điều kiện quyết định kiến trúc bên dưới hoặc user yêu cầu rõ.

Tạo hoặc cập nhật ADR khi task đưa ra quyết định có ảnh hưởng dài hạn hoặc cross-team như: chọn công nghệ/framework/database/message broker, đổi API/auth/data boundary, thay đổi observability/security/deployment strategy, migration lớn, hoặc rule kiến trúc mà future dev cần biết lý do.

ADR tối thiểu gồm title tiếng Anh ngắn gọn và body tiếng Việt (status `proposed`/`accepted`/`superseded`, date, context, decision, alternatives, consequences, links). Mỗi ADR một quyết định; quyết định cũ bị thay thế thì tạo ADR mới và mark bản cũ `superseded`. Chi tiết format, quy ước tên file và template ở `.agents/references/adr-format.md`.

Với task có Jira và có ADR, khi hoàn tất comment vào Jira bằng TWG kèm link ADR/Confluence, file/module chính, verification, risk còn lại và footer `ADLC AI provenance`. Mọi Confluence page/comment do ADLC tạo hoặc cập nhật cũng upsert footer này. Không đưa raw log, secret, PII hoặc payload nhạy cảm vào ADR/Confluence/Jira comment.

## Skill Routing Theo Intent

Agent tự resolve workspace, risk và intent để chọn skill; user không phải biết hoặc chỉ định tên skill. Chỉ dùng skill có liên quan và không tạo Workflow Control run chỉ để gọi skill.

Tên skill trong bảng dưới đây là `.agents/skills/<tên>/SKILL.md` — đọc và thực thi trực tiếp theo file đó, **không** qua Claude Code `Skill` tool (chỉ `agent-teams`, `drawio-skill`, `impeccable` được bridge vào `.claude/skills/`; các skill lifecycle như `/dev`, `/qc`, `/sec`, `/review` cố tình không đăng ký vào `Skill` tool để tránh bị gọi ngoài một run). Khi intent khớp một hàng trong bảng, **cấm** dùng skill built-in cùng tên/nghĩa để thay thế (vd Claude Code `code-review`, `simplify`, `security-review`) — chúng thiếu evidence ADLC yêu cầu (Jira/AC, CodeGraph impact, ma trận an ninh...). "Skill review có vẻ không tồn tại trong danh sách Skill tool" không phải lý do fallback — đọc thẳng `.agents/skills/review/SKILL.md`.

## Conditional Domain Design

`/domain` chỉ chạy khi request có domain-risk: bounded context/service hoặc
business capability mới, aggregate lifecycle/business invariant, chuyển data
ownership, cross-service event choreography, hoặc payment/medical/regulated
workflow phức tạp. Ordinary CRUD dùng rule hiện có, bugfix cục bộ, refactor
không đổi behavior, docs, UI-only và infrastructure-only phải `SKIP`.

Khi chạy, `/domain` xác định boundary, ubiquitous language, ownership,
aggregate/entity/value object, invariant, command/domain event, consistency và
traceability trong `docs/domain/<context>/domain-model.md`. Chỉ tạo
`context-map.md` khi có từ hai context thật sự tương tác. Chưa rõ ownership,
invariant mâu thuẫn, event thiếu producer/consumer hoặc contract liên context
thiếu compatibility decision thì `BLOCKED`; thiếu diagram trang trí không block.

Domain Design không phải quality gate mặc định. Nó route HTTP/event contract
qua `/api`, observable invariant qua `/qc`, ADR khi có quyết định kiến trúc dài
hạn và implementation qua `/dev`. Domain artifact không thay source, contract,
test, build hoặc runtime evidence.

## Project Context Bootstrap

Khi `.project-contexts/` chưa tồn tại, thiếu workspace được chạm, hoặc facts trong context mâu thuẫn với README/manifest/remote hiện tại, agent tự bootstrap theo thứ tự sau trước khi delivery work:

1. Tạo/refresh `workspaces.json` từ cấu trúc repo, submodule, manifest và workspace root; không đoán framework nếu chưa có manifest.
2. Tạo/refresh `project-context.md` để route workspace và chỉ tạo `workspaces/<id>.context.md` cho workspace có facts ổn định cần dùng lại. Dùng `_template.md`, ghi source và command đã xác minh.
3. Chỉ tạo/cập nhật `work-tracking.json` khi có Jira/Confluence/GitFlow source đáng tin cậy (config hiện có, URL/key user đưa, hoặc discovery read-only đã xác minh). Không bịa board ID, sprint, project, URL hay target branch; thiếu fact thì để optional và hỏi đúng lúc task cần mutation.
4. Chỉ tạo/cập nhật `api-governance.context.md` khi project có API governance source. Không copy endpoint/IDP convention từ project khác.

Bootstrap là thay đổi metadata có thể review: báo file context đã tạo/cập nhật, source đã dùng và phần còn chưa xác minh. Không cần workflow run chỉ vì bootstrap; Jira gate vẫn áp dụng nếu context update là một thay đổi quy trình đáng kể.

ADLC để lại ba tên ẩn ở gốc project — `.ADLC.md`, `.graphify-out/`, `.graph-out/` — và `adlc setup`/`adlc upgrade` thêm ba tên đó vào `.gitignore` của project (`.agents/` cũng vậy: CLI dựng lại được). Project onboard trước đây còn mang tên cũ không có dấu chấm; mọi lệnh đọc được cả hai, đừng sửa tay. Chi tiết: `.agents/SETUP_GUIDE.md`.

## Local Business Documents

Khi request có `@docs/<path>` hoặc path dưới `docs/`, agent phải phân loại tài liệu trước khi dùng làm evidence. `@docs` là source reference, không tự động có nghĩa là business truth.

- Chạy `python3 .agents/skills/ba/scripts/document_source_tool.py` để lấy `category`, `authority`, `status`, `evidence` và source anchor của tài liệu liên quan.
- `doc_type` nghiệp vụ cùng `authority: accepted` và `status: active` mới là business evidence `VERIFIED`; tên file/thư mục chỉ là heuristic để route `/ba`.
- Tài liệu accepted định nghĩa target behavior; Jira/Confluence/BRD định nghĩa approved scope khi đã cấu hình; code/test chứng minh current behavior.
- Draft, stale, unclassified hoặc conflicting document là `NOT_VERIFIED`; `/ba` phải ghi conflict/source section và không được tự chọn business rule.
- Business document reference luôn giữ `/ba` step `EXECUTE`; `/domain` chỉ thêm khi có boundary, ownership, invariant hoặc event risk. Tài liệu kỹ thuật không được tự kích hoạt `/ba` nếu behavior đã rõ.
- Chỉ hydrate section liên quan; không quét hoặc đưa toàn bộ `docs/` vào prompt/log/artifact.

### Jira live và độ tươi của tài liệu

- Với delivery task có Jira, đọc issue/AC/comment quyết định **live** trước khi dùng bản sao hoặc tài liệu local. Jira hiện hành định nghĩa task scope khi đúng project, còn hiệu lực và có authority/approval theo project policy.
- `docs/` giữ business rule, domain knowledge, ADR và contract ổn định; không bắt buộc mirror từng field/status/comment ngắn hạn của Jira.
- Nếu Jira được phê duyệt ghi rõ `supersedes` một tài liệu cũ, route `/ba` với `DOC_STALE`/`JIRA_SUPERSEDES_DOC`. Nếu hai nguồn mâu thuẫn nhưng không có supersede/authority rõ, ghi `BUSINESS_CONFLICT` và không tự chọn một phía.
- Thiếu hoặc stale supporting docs không tự chặn implementation khi Jira live đã đủ rõ và được xác minh. Chỉ contradiction chưa giải quyết mới là blocker.

### Sinh deliverable mới (PRD/spec/meeting notes)

Đây là việc *tạo mới* một tài liệu nghiệp vụ, khác với việc phân loại tài liệu có sẵn ở trên. Chỉ sinh file khi task thật sự cần một deliverable có audience ngoài phiên chat và vòng đời riêng — PRD, tech spec, meeting notes, retro — không sinh file cho câu trả lời một lần dùng xong hay giải thích code.

- Ghi file markdown tại `docs/` (path theo quy ước hiện có của project context, ví dụ `docs/prd/`, `docs/adr/` cho ADR); không tạo file rác ngoài `docs/`.
- Không tự động push Confluence. Confluence MCP đã có sẵn (`createConfluencePage`/`updateConfluencePage`); chỉ dùng khi user yêu cầu publish, không suy luận thời điểm push.
- ADR đi theo ADR/Confluence Gate ở trên khi task là quyết định kiến trúc; các deliverable khác (PRD, spec) không cần điều kiện đó.

Semantic Context (tên nội bộ trước đây: Graphify) là optional retrieval trên nội dung của workspace — mặc định cả workspace, không còn giới hạn trong `docs/` — và không phải business truth, quality gate hay release evidence; query result phải giữ provenance và đi qua authority/status rules phía trên. Cách init/query, backend rules và giới hạn ở `.agents/references/document-intelligence.md`; đọc khi thực sự dùng.

## Optional Code Intelligence

CodeGraph là optional read-only code intelligence — không phải quality gate hay delivery evidence. Chọn graph theo **Git repository/workspace đang đổi**; không dùng một graph global thay graph của từng service/submodule. Khi `.codegraph/` có ở root của workspace bị chạm, dùng CodeGraph trước `rg`/đọc file cho câu hỏi về symbol, flow, caller/callee, dependency hoặc impact. CodeGraph mô tả AS-IS; `/domain` sở hữu boundary/invariant TO-BE. Tool thiếu, index stale hoặc cần nội dung vừa sửa thì dùng source hiện tại và báo `CodeGraph: NOT AVAILABLE`/`STALE`/`ERROR`, không block delivery. `adlc setup`, `adlc scan` và Extension tự resolve từng Git repository trong trusted workspace: chạy `codegraph init` khi graph thiếu, `codegraph sync` khi graph đã có; `.codegraph/` là local state ghi Git local exclude, không sửa tracked `.gitignore`. Install/opt-out ở `SETUP_GUIDE.md`.

**Lifecycle Graph** (`adlc graph init|build|query|pack|doctor|show`; MCP `adlc_graph_query`, `adlc_graph_pack`, `adlc_graph_build`, `adlc_graph_doctor`) là optional intelligence cross-repo: pre-compute liên kết service ↔ endpoint ↔ handler ↔ test ↔ consumer từ artifact đã có. Nó được phép suy quan hệ giữa các repo với điều kiện **mọi cạnh mang mức tin cậy** `declared`/`derived`/`inferred`; cạnh `inferred` không bao giờ là delivery evidence (ADR `allow-cross-repo-lifecycle-graph-with-confidence-labels`). Graph mô tả AS-IS; thiếu/stale thì báo trạng thái rồi đi tiếp, không block. Với composer routing, tín hiệu từ graph **chỉ được thêm skill, không bao giờ được bớt**. Chọn công cụ: symbol/caller/blast-radius trong một repo → `codegraph_explore`; vượt biên repo hoặc chạm API/DB/test/deploy → `adlc graph query`; tài liệu nghiệp vụ → `adlc docs-query`. `.graph-out/` là local state ghi Git local exclude. Pack nào cho skill nào, cách trích dẫn mức tin cậy và quy tắc chỉ-leo-thang ở `.agents/references/lifecycle-graph-usage.md`.

**Semantic Context graph** (`adlc path <A> <B>` / `adlc explain <X>`; MCP `adlc_path`, `adlc_explain`) đọc `.graphify-out/graph.json` để vẽ **đường đi giữa 2 phần code** hoặc **một node + hàng xóm** dưới dạng sơ đồ. Khi đang coding và cần giải thích quan hệ / blast-radius / dependency giữa các symbol, file, hay module — **dùng lệnh này thay vì mô tả bằng text dài**, vì sơ đồ khó nhầm hơn chuỗi chữ. Kết quả trả về khối ` ```mermaid `; **emit khối đó nguyên vẹn vào câu trả lời** để người dùng xem sơ đồ trực quan (click để phóng to). Graph mô tả AS-IS; thiếu `.graphify-out/graph.json` thì báo `Semantic Context: NOT AVAILABLE` và đi tiếp, không block.

## Quality Gates

- Thay đổi behavior/contract phải có unit test hoặc focused automated test viết **trước** implementation, chạy đỏ đúng nguyên nhân rồi mới làm xanh. Test-first nghĩa là một **bộ case được thiết kế** chứ không phải một test ứng biến: case suy từ AC bằng kỹ thuật khớp (equivalence partitioning, boundary, decision table, state transition), mỗi case gán đúng một layer, tên test mang case ID để truy vết AC ↔ case ↔ test; pass 100% trên tập case không thiết kế không phải bằng chứng. Kết quả test chỉ được kết luận từ **quan sát** trên runtime thật, không suy từ spec hay code (`.agents/skills/qc/references/test-case-standard.md`). Refactor/bugfix rõ được mở rộng regression test gần nhất nhưng vẫn phải chứng minh test bắt được lỗi. Property-based, resiliency/fault-injection và journey E2E chỉ bắt buộc khi `/qc` trigger khớp (`references/advanced-test-strategies.md`); không tách skill riêng và không nâng risk chỉ vì có HTTP/API.
- Line coverage tối thiểu `85%`. Workspace legacy chưa đạt thì changed scope phải đạt 85% và coverage tổng không được giảm; ngoại lệ phải có Jira, owner, lý do và ngày hết hạn. Coverage chỉ là gate khi command trả lỗi dưới ngưỡng, không chỉ in report.
- Unit test nằm trong native test root. `/qc` chọn layer hẹp nhất chứng minh contract: unit/focused cho rule cục bộ; integration/functional test cho API, persistence hoặc service boundary; Playwright hoặc runner chuẩn của workspace cho user journey UI → gateway → API; executable acceptance cho CLI/job. E2E bổ sung chứ không thay unit test. Manual exploratory/UAT là ngoại lệ phải có lý do, owner và expiry; Qase, manual CSV và per-change Confluence case không còn là delivery gate mặc định.
- Journey/E2E test phải có tier đóng khung thời gian: Smoke 5 phút (mỗi lần deploy môi trường test, gãy thì trả build), Core 20 phút (mỗi ticket ready-to-test), Full nightly/trước release. Vượt trần là tín hiệu phải rà lại test nào còn giá trị, không phải lý do nâng trần — báo overrun trong handoff. Spec do agent sinh (thường là regression để lại sau bugfix) vào **quarantine** trước, CI chạy nhưng không làm đỏ pipeline, và chỉ được promote vào suite chính sau **3 lần pass liên tiếp trên 2 build khác nhau**. Chi tiết ở `.agents/skills/qc/references/advanced-test-strategies.md`.
- Sau mỗi workflow có ít nhất một integration/E2E result đã thực thi, publish đúng một Confluence workflow E2E summary đã curate khi project cấu hình đích; dedupe bằng `workflowRunId`, append theo snapshot token và rollover rule ở `.agents/skills/qc/references/confluence-e2e-report.md`. Không có executable cross-boundary result thì SKIP kèm lý do. Raw report, source assertion, log, token, PII và production payload không lên Confluence.
- API mới hoặc đổi contract phải tự route qua `/api`, chạy focused contract test và IDP plan/validation. `/api` tự chọn onboarding, contract, catalog hoặc no-drift work theo change class; không đoán metadata và không regenerate reviewed bundle mù.
- Behavior mới hoặc được fix có bề mặt chạy được phải được agent tự kiểm chứng end-to-end trên runtime thật trước handoff: UI đi qua flow bằng browser tool, API gọi thật endpoint, CLI/job chạy lệnh thật theo `verify_steps`. Unit test xanh không thay được bước này. Không dựng được runtime thì ghi `RUNTIME NOT VERIFIED` kèm lý do và cách verify thay thế, không suy ra PASS (`.agents/references/session-lifecycle.md`).
- Automation chạy trên máy dev chỉ được tính là evidence khi MR kèm execution manifest `quality/executions/<jira-key>/<execution-id>.json` (mỗi kết quả mang case ID + layer, chạy đúng MR head). `/review` verify bằng `test_execution_tool.py review --head <sha>` và ghi rõ layer nào đã chạy, layer nào chưa; manifest stale/thiếu layer/thiếu bằng chứng → `NOT VERIFIED`, chặn merge. CI có job tương đương thì CI là gate; manifest bù cho phần CI chưa chạy được.
- Auth/authz phải kiểm tra `401/403` và ownership/data scope khi có. Persistence phải xem migration, index/constraint và rollback nếu deploy; UI phải kiểm tra state/accessibility bị chạm.
- PII/secret/payment/medical/external integration phải qua `/sec`; scanner không thay thế negative test và không đưa dữ liệu nhạy cảm vào log, trace, artifact hoặc ticket comment.
- `/sec` triage diff trước, chỉ chạy semantic deep review khi chạm auth/data/PII/injection/crypto/external/security boundary hoặc user yêu cầu. Semantic review dùng coding-agent session hiện tại, không gọi thêm LLM/filter API mặc định; phải pin exact base/head ref, account mọi changed file và validate structured output. Error, timeout, skipped, stale ref, incomplete coverage hoặc invalid output là `NOT VERIFIED`, không phải zero-finding PASS.
- **Secret không được rời máy.** Mọi push đi qua pre-push secret gate (`.agents/orchestration/scripts/secret_gate.py`, cài hook bằng `install_hooks.py`; `gitflow_tool.py ship` tự gọi). Gate quét đúng các commit sắp push và **chặn** khi có finding — chặn, không phải cảnh báo, vì gitleaks trong CI chạy *sau* push. Thiếu `gitleaks` là `NOT VERIFIED` nên fail-closed; bypass bằng `--no-verify` phải nêu trong handoff kèm lý do.
- CI/build/audit local không phải CI PASS. Chỉ gọi CI PASS khi blocking job đúng commit/ref đã xanh; job skipped, `allow_failure` hoặc audit-only phải nói rõ.
- Kết quả scanner phải khai đúng tầng độ tin cậy (`LOCAL-INDICATIVE`/`CI-PARITY`/`NOT VERIFIED`), secret scan + SAST áp cho mọi changed file (tín hiệu pre-MR qua `local_scan_tool` của `/sec`), gate dependency trung tâm chặn theo Threat Intelligence blacklist và không theo CVSS severity, suppression phải qua `scan_ignore` có owner/lý do/thời hạn, pipeline mâu thuẫn Quality Gate thì báo `POLICY DRIFT`. Từng rule ở `.agents/references/security-scan-policy.md`.

## Workflow Control Và AI Prototype

Workflow Control là tùy chọn cho hỏi đáp/review/docs nhỏ, nhưng bắt buộc khi task cần audit trail: delivery work có Jira, có ADR/Confluence, critical/AI workflow, hoặc user yêu cầu trace ADLC. Dùng `python3 .agents/orchestration/scripts/workflow_runner.py validate` để kiểm tra registry.

### Orchestration mechanisms

- **Workflow Engine**: fan-out/pipeline 1 agent qua `agent()`/`parallel()`/`pipeline()` — `.agents/references/workflow-engine.md`.
- **Multi-Provider Subagent**: 6 providers (`in-process` mặc định, `fork`, `external-cli`, `acp`, `sdk`, `remote`), chọn qua `subagent_resolver.py resolve` — `.agents/references/subagent-providers.md`.
- **Ralph Loop**: fresh-agent iteration, handoff giữa round, max-rounds + block detection — `.agents/references/ralph-loop.md`.
- **Agent Teams** (`adlc team`): roster + task DAG + mailbox bền — `.agents/references/agent-teams.md`.

Chọn cơ chế nào: `.agents/references/orchestration-decision-matrix.md`.

Khi tạo run, Langfuse trace là audit trail cho ADLC orchestration: prompt đã giao, workspace/source/Jira, step nào RUNNING/DONE/ERROR/SKIPPED, artifact nào sinh ra, test/security/runtime evidence, ADR/Confluence và Jira completion comment đã làm chưa. Không trace secret, token, raw PII, raw production payload hoặc full log nhạy cảm.

Luồng tối thiểu cho task có run: `init-run` → `trace-prompt` khi giao prompt chính → `update-step --status RUNNING|DONE|ERROR|SKIPPED` từng bước → `trace-prompt --completion-status completed --final-step` cho handoff cuối. Không gọi `trace-output` sau mọi `update-step DONE` (nhân đôi trace và token). Chi tiết trace naming/tags, token usage override và các bước ở `.agents/references/workflow-control-operations.md`; đọc khi thực sự tạo run.

AI/agent feature cần prototype/eval trước production: hypothesis, boundary, golden cases, tool contract, run report, cost-latency và quyết định `GO`/`NO-GO`/`ITERATE`. Dùng `$langfuse` khi cần trace, prompt, dataset hoặc score.

## Definition Of Done

- Scope, primary workspace và affected workspace đúng.
- Thay đổi tối thiểu, theo pattern hiện có; không vô tình đổi contract/auth/data model.
- Verification/security/runtime evidence tỷ lệ với risk, hoặc nêu rõ lý do không chạy được.
- MR creation/review có bảng DoD trực quan và visual evidence liên quan khi khả dụng theo `.agents/references/mr-visual-evidence.md`: ảnh capture UI/hội thoại thật hoặc rendered summary ghi rõ nguồn, head và kết quả; upload/link được xác minh hoặc ghi `NOT AVAILABLE`/`N/A` + lý do. Ảnh không thay thế test/coverage/runtime evidence.
- Khi contract HTTP đổi, OpenAPI runtime/service và `docs/idp/{service-id}/openapi.yaml` phải đồng bộ, `registry.yaml` phải khớp method/path hai chiều, và local IDP validation phải đạt; CI/IDP approval/runtime proof báo riêng.
- ADR/Confluence cập nhật khi có quyết định kiến trúc đáng ghi lại.
- Unit/focused tests được chạy và coverage gate có scope/report/percentage rõ. Integration/E2E/runtime evidence được chạy khi boundary bị chạm, hoặc ghi `NOT VERIFIED`/SKIP đúng lý do; Jira/MR handoff link native evidence, defect và Confluence workflow E2E summary khi đã publish.
- Session lifecycle sạch theo **Session Lifecycle Gate**: healthcheck/E2E runtime evidence cuối (hoặc `RUNTIME NOT VERIFIED` kèm lý do), không file rác/process lơ lửng, ledger/task list phản ánh đúng trạng thái, việc còn dở ghi rõ.
- Sửa bug xong thì ghi bài học vào `lessons.json` ở root project (file **được track**, review trong MR — store nằm trên một máy thì chỉ dạy được máy đó): `lesson_tool.py add --symptom … --root-cause … --guard …`. **Cảnh gác** là bắt buộc — một bài học không nói được lần sau chặn bằng gì chỉ là ghi chú về quá khứ, và tool từ chối. Nguyên nhân đã có thì tool báo lại và hỏi `--same-as` hay `--new`; `seen > 1` nghĩa là cảnh gác cũ không chặn được, sửa nó bằng `reguard` chứ không ghi bài học mới. Đọc trước khi làm: `lesson_tool.py recall "<việc sắp làm>"`.
- Handoff nêu file đổi, lệnh đã chạy, kết quả, branch/Jira nếu có và risk còn lại.
